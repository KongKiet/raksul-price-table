## Goal

Decompose `App.tsx` into logical, single-responsibility components under `src/components/`, so that `App.tsx` owns state and wiring only and composes extracted components rather than containing their markup directly. This is a pure refactor: no visible layout, styling, or behavior change, and no new functionality.

## Inspection and dependency evidence

Inspected on 2026-09-10.

- T00–T06 are implemented, verified, and shipped (T00 and T01 through T02 committed; T03–T06 shipped to `origin/main` through commit `1ce5592`). They supply the full current feature set: tooling, the price formatter, the A4 table with loading/error/retry/empty states, paper-size selection and Apply with stale-request protection, cell selection and derived Order price, See more, and hover highlighting.
- `src/App.tsx` (175 lines) currently contains: the page header/intro, an inline paper-size `<form>` (draft select + Apply button), a panel section with the `appliedPaperSize` heading badge, inline loading/error/empty status markup, the `<PriceTable>` element, and an inline Order price label/value block. All interaction state (`draftPaperSize`, `appliedPaperSize`, `selectedCell`, `hoveredCell`, `showAllRows`) lives in `App` as plain `useState`, and `selectedPrice` is derived, not stored.
- `src/components/PriceTable/PriceTable.tsx` is already its own component with a co-located CSS Module (`PriceTable.module.css`), establishing the folder convention (`src/components/<Name>/<Name>.tsx` + `<Name>.module.css`) this task should follow.

- No state management library, context, or store exists anywhere in `src`; all state is lifted `useState` in `App`, per the documented "React local state" decision. This task does not change that.
- T08 (cart-ready layout) and T09 (Add to Cart functionality) depend on this task's component boundaries to add the Add to Cart bar and cart icon without further restructuring `App.tsx`.

No dependency capability or unresolved product input blocks implementation.

## Acceptance criteria

1. `App.tsx` renders only top-level composition: it owns `usePrices`, the five pieces of interaction state, derived `selectedPrice`, and event handlers, and renders extracted components — it contains no `<form>`, table-status, or Order-price markup directly.
2. A paper-size form component (e.g. `PaperSizeForm`) receives the list of sizes, the draft value, and callbacks, and renders the existing `<select>` and Apply `<button>` with identical accessible names, `id`/`for` associations, and keyboard behavior.
3. A price-status component (e.g. `PriceStatusMessage`) renders the existing loading spinner, error message with retry button, and empty-state message, preserving existing `role="status"`/`role="alert"` and `aria-live` usage exactly.
4. An order-price component (e.g. `OrderPriceSummary`) renders the existing label/value pair, preserving the em dash before selection, the derived formatted price after selection, and the existing `aria-live="polite"` behavior.
5. A composing panel component (e.g. `PricePanel`) assembles the `appliedPaperSize` heading badge, the status component, `PriceTable`, and the order-price component in the existing order, matching current DOM structure closely enough that existing tests and visual output are unaffected.
6. Every extracted component lives under `src/components/<Name>/` with a co-located CSS Module; class names and selectors are renamed or relocated as needed but produce the same computed styles as before (no visual diff).
7. `PriceTable.tsx` and its existing props/behavior (selection, hover, See more) are unchanged by this task.
8. No new dependency, global store, context, or routing is introduced; state remains lifted `useState` in `App`, passed down as props.
9. All existing automated tests pass without weakening assertions; tests may be moved or split to align with new component boundaries, but observable coverage (loading/error/retry/empty, Apply, selection, See more, hover, stale-request handling) is preserved.
10. The final diff is scoped to this refactor (no unrelated formatting-only churn); formatter/lint/tests/build pass, and a real browser check confirms the page is visually and behaviorally identical to before the refactor.

## Scope and non-goals

Scope: extracting `PaperSizeForm`, `PriceStatusMessage`, `OrderPriceSummary`, and a composing `PricePanel` (or an equivalent logical split arrived at during implementation) from `App.tsx`; relocating their styles into co-located CSS Modules; keeping `PriceTable` as-is; updating/reorganizing tests to match.

Do not change visible layout, styling, copy, or any interaction behavior; do not add cart UI, a cart icon, a notification, a modal, or any new state (those belong to T08 and T09); do not introduce a global store, context, routing, or new dependencies; do not change the API layer, `usePrices`, or `formatPrice`.

## Implementation assumptions

These task-level choices are separate from assignment requirements:

- Exact component names and the precise split (e.g. whether `PriceStatusMessage` is one component with a discriminated-union prop or is folded into `PricePanel`) are an implementation detail decided during T07 implementation, as long as the resulting boundaries are logical, single-responsibility, and satisfy the acceptance criteria above.
- Props between `App` and its children continue to be plain, explicitly typed objects/callbacks (no new abstraction layer such as a context provider or reducer), consistent with the existing "React local state" decision.
- CSS Modules are split along the same lines as the components; shared values continue to come from `src/index.css` tokens rather than being duplicated into new modules.

## Risks and blockers

No unresolved blocker prevents implementation.
