## Goal

Implement cart behavior on top of T08's layout: clicking Add to Cart adds the selected item to cart state and shows a small success notification matching the project's style; clicking the cart icon opens a modal showing cart contents with quantity controls, item removal, an empty-cart state, scrolling for long lists, a total price, and a Checkout button that is disabled when the cart is empty. Cart contents are persisted to `localStorage` so a page refresh does not clear the cart.

## Acceptance criteria

1. Clicking the enabled Add to Cart button adds a cart line identified by `{ paperSize, quantity, businessDay }` with its `price` and a cart `quantity` (order count) of 1; clicking Add to Cart again for the same identity increments that line's cart quantity instead of creating a duplicate line.
2. After a successful add, a small success notification appears, styled consistently with the project's existing status/feedback conventions, and disappears on its own after a short duration (auto-dismiss) without requiring user action; it does not block interaction with the rest of the page.
3. The cart icon button opens a modal (native `<dialog>` or `role="dialog"` with focus trapped and restored, closable via an explicit close control and the Escape key) showing current cart contents.
4. When the cart is empty, the modal shows a clear empty-cart message instead of an item list, and the Checkout button is disabled.
5. When the cart has items, each line displays the paper size, quantity (order count), and business days, plus its line price (via `formatPrice`); the list scrolls within the modal (not the page) when it exceeds the modal's visible height, keeping the total/Checkout footer visible.
6. Each line has controls to increase and decrease its cart quantity (decreasing to zero removes the line) and a control to remove the line outright regardless of quantity.
7. The modal shows a computed total price (sum of line price × cart quantity for each line, formatted via `formatPrice`) that updates immediately as quantities change or lines are removed.
8. A Checkout button is shown at the bottom of the modal; it is disabled whenever the cart is empty and enabled otherwise; clicking it while enabled performs no real checkout/payment processing (no network request, no navigation).
9. Cart state remains plain React local state during the session and is also persisted to `localStorage` on every change (add, increment, decrement, remove), so that reloading the page restores the same cart contents (line items and quantities) instead of clearing it. Persistence does not introduce a global store, context, or backend. Cart state is unaffected by paper-size Apply, selection, hover, or See more changes elsewhere in the app.
10. If `localStorage` is unavailable (e.g. disabled by the browser), empty, or contains data that fails to parse or does not match the expected cart-line shape, the cart initializes empty rather than throwing or crashing the app.
11. All interactive elements (notification's implicit dismissal, modal open/close, quantity controls, remove controls, Checkout) are keyboard-operable with visible focus and appropriate accessible names/roles.
12. Automated tests cover: adding a new line, incrementing an existing line, the notification appearing, opening/closing the modal, the empty-cart state, quantity increase/decrease (including decrementing to removal), explicit removal, total-price computation, the Checkout button's disabled/enabled transitions, cart contents surviving a simulated reload, and graceful handling of missing/corrupt stored data — all without a live API dependency.
13. The final diff is scoped; acceptance criteria and the diff are inspected; tests, formatter, lint, and build pass; a real Chrome or Firefox check confirms the notification, modal interaction, scrolling, responsive behavior, and that a manual page refresh preserves the cart.

## Scope and non-goals

Scope: cart state (add/increment/decrement/remove), a success notification component, a cart modal component with empty/populated/scrolling states, quantity and removal controls, total-price computation, a disabled-when-empty Checkout button with no real checkout processing, and persisting cart contents to `localStorage` so they survive a page refresh.

Do not implement real checkout/payment, order submission, routing, a global store, or a backend — `localStorage` is a browser-only, client-side persistence mechanism and does not introduce a backend or server-side storage. Do not change selection, hover, See more, Apply, API behavior, or the price formatter itself. Do not alter T08's layout beyond wiring existing controls' handlers. Do not implement versioning/migration for the stored cart shape; this is the first version of persisted data.

## Implementation assumptions

These task-level choices are separate from assignment requirements:

- Cart state is an array of line items keyed by `{ paperSize, quantity, businessDay }`, held in `App` (or a small dedicated hook such as `useCart` colocated with `App`) as plain `useState`, per the "React local state" decision; no context or external store is introduced.
- The success notification auto-dismisses after a short fixed duration (e.g. a few seconds); exact timing is an implementation detail, not a product requirement.
- The cart modal is implemented with the native `<dialog>` element when practical (native focus trapping, `::backdrop`, and `Escape`-to-close), falling back to a manually managed `role="dialog"` implementation only if `<dialog>` proves insufficient for required styling/behavior.
- "Business days" in each cart line refers to the selected cell's `business_day` value carried at the time of Add to Cart, consistent with how it is already identified elsewhere (T04/T06).
- Decreasing a line's quantity below 1 removes the line, rather than allowing a zero-quantity line to remain visible.
- Cart data is persisted under a single dedicated `localStorage` key (e.g. `raksul-price-table:cart`; the exact key is an implementation detail decided during implementation) as JSON-serialized cart lines.
- The cart's initial state is read from `localStorage` lazily on first render (e.g. `useState(() => readCart())`), and a `useEffect` writes the current cart to `localStorage` whenever it changes; both the read and the write are wrapped in `try`/`catch` so a disabled/unavailable store, a quota error, or malformed stored JSON falls back to an empty cart / is silently ignored rather than crashing the app or surfacing an error to the user.
- Stored data is validated at read time against the expected shape (paper size, quantity, business day, price, cart quantity); anything that does not match is treated as absent (empty cart) rather than partially trusted.

No unresolved blocker prevents implementation.

## Progress and verification evidence

Implemented on 2026-09-10.

- `src/hooks/useCart.ts` (new): a `useCart` hook owning cart state as `CartLine[]` (`{ paperSize, quantity, businessDay, price, cartQuantity }`), with `addItem` (adds a new line or increments an existing one identified by `{ paperSize, quantity, businessDay }`), `incrementLine`, `decrementLine` (filters the line out once `cartQuantity` reaches 0), `removeLine`, and a derived `total`.
