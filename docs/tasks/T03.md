## Goal

Add an accessible paper-size selector and Apply action for A4, A5, B4, and B5. Keep the dropdown choice separate from the applied size, request new prices only when a different size is applied, and prevent superseded requests from affecting current loading, data, or error state.

## Acceptance criteria

1. The page has a visibly labeled native selector with exactly A4, A5, B4, and B5 plus an accessible Apply control. A4 is selected and applied initially.
2. Changing only the selector updates the draft choice but does not request prices, change applied-size labels, replace the current table, or alter the current error/empty state.
3. Applying a different draft updates the applied size and requests that exact supported value. Applying the already-applied value makes no redundant request.
4. Immediately after applying a different size, the UI shows loading for that size and no previous table, error, or empty state, including before the request effect starts.
5. A successful response renders the existing table behavior with heading, badge, caption/region label, and empty copy associated with the applied size rather than hardcoded A4 text.
6. Retry requests the currently applied size. An unapplied draft cannot change Retry ownership.
7. Applying another size aborts and invalidates the superseded request. Its delayed success, failure, or completion cannot replace current state or clear current loading, even if it settles despite abort.
8. Only the first five usable rows render after every applied-size response; T03 adds no expansion or follow-up request.
9. Selector and Apply work by keyboard, have understandable names, and retain visible focus at desktop and narrow widths.
10. T03 adds no selection, Order price, See more, hover, Cart behavior, routing, global state, or mock fallback. T04-T06 own future interaction-state resets.
11. Controlled automated tests cover initial A4, all options, draft-only changes, Apply, same-size no-op, size-aware Retry, five-row behavior, and overlapping requests without using the live API.
12. The final diff is scoped; focused/full tests, formatting, lint, and build pass; real latest Chrome or Firefox verifies the controls, transitions, focus, and responsive layout.

## Implementation assumptions

These are task-level choices, separate from assignment requirements:

- Keep `draftPaperSize` and `appliedPaperSize` as separate `PaperSize` values in `App`, both initialized to `A4`.
- Use a semantic form with a native `select`, visible label, and submit button so button activation and Enter share Apply behavior.
- Store the four supported values in a typed constant rather than spreading arbitrary string casts through the component.
- Treat same-size Apply as a no-op. The control may remain enabled; no disabled-state requirement is introduced.
- Tag request state with its paper size, or use an equivalent ownership projection, so a hook render whose state owner differs from the current argument exposes clean loading rather than old data/error before `useEffect` runs.
- At each request start, clear visible data/error and establish loading for that size. Preserve the monotonic request identity, AbortController cleanup, and guards in `then`, `catch`, and `finally`.
- Retry remains inside `usePrices` and retries its current applied-size argument. Draft-only changes never reach the hook.
- Derive labels from `appliedPaperSize`. The documented API contract owns response correspondence; T03 adds no undocumented request/response mismatch policy.
- The existing five-row projection satisfies T03's observable reset because expansion does not yet exist. T05 will add mutable expansion reset; T04 and T06 will add their own selection/hover resets.

## Risks and blockers

- Effects begin after render. Clearing data only inside the effect can briefly label the previous table as the newly applied size; render-time request ownership must prevent this.
- Strict Mode starts and cleans up effects twice. Tests must account for its initial lifecycle while proving stale settlements remain harmless.
- A mock or transport can settle after abort. Abort alone is insufficient; every state write, including `finally`, needs identity protection.
- Draft and applied sizes can differ during an error. Retry must not bypass Apply by using the draft value.
- Native select values are strings. Keep conversion constrained to the fixed typed options.
- The table always shows five rows, so T03 cannot demonstrate reset from an expanded state. T05 owns that transition; do not add dormant expansion state.
- The missing mockup prevents exact comparison; requirements-based browser QA is still required.
- Earlier shipping records are locally modified and stale after the GitHub push. Preserve them during T03 and reconcile only in an authorized shipping workflow.

No unresolved blocker prevents implementation.
