## Goal

Let users select an available price by pointer or keyboard, keep the chosen cell visibly selected, and show its formatted value as Order price. Store selection by quantity and business day, derive the displayed price from current response data, and clear selection when a different paper size is applied.

## Acceptance criteria

1. Before selection, a visibly labeled Order price area displays an em dash.
2. Every available visible price is a native control activated by pointer, Enter, or Space, with an accessible name identifying price, quantity, and business day.
3. Activation selects the quantity/business-day pair, persistently highlights exactly that cell, and exposes selected state programmatically.
4. Another available cell replaces the selection; activating the selected cell again is idempotent rather than toggling it off.
5. Order price is derived by locating the identity in current response data and formatting that entry with formatPrice. It is not stored independently or multiplied by quantity.
6. Equal displayed prices remain distinct because identity uses quantity and business day, not price value or array position.
7. Missing combinations remain visibly and accessibly unavailable, contain no selection control, and cannot change selection or Order price.
8. Draft-only size changes and same-size Apply preserve selection. Applying a different size clears it immediately and leaves it cleared through loading, failure, empty data, success, and stale settlement.
9. Selection does not change the five-row limit, issue a request, mutate response data, or add hover, See more, Cart, routing, global state, or fallback behavior.
10. Selected and focus styles are distinguishable at desktop and narrow widths, remain legible with stripes and scrolling, and do not rely on color alone for focus.
11. Controlled tests cover initial state, pointer and keyboard selection, replacement and idempotence, identity collisions, unavailable cells, formatting, preservation, and reset without live API calls.
12. The final diff is scoped; focused/full tests, formatting, lint, and build pass; latest Chrome or Firefox verifies selection, Order price, resets, focus, and responsive interaction.

## Implementation assumptions

These task-level choices are separate from assignment requirements:

- Define a selected identity with numeric quantity and businessDay fields in App, which owns current data and the applied-size transition.
- Pass selected identity and an onSelect callback to PriceTable; keep response mapping and cell rendering inside that component.
- Render each available price as a button with type button that fills its table cell. Native activation supplies pointer, Enter, and Space behavior.
- Give each button a contextual accessible name and aria-pressed state. Keep unavailable cells noninteractive with existing Unavailable text.
- Repeated activation of the selected cell is a no-op because requirements specify persistent selection and replacement, not toggle-to-clear.
- Derive the entry from data.prices and identity during render. If no current entry matches, display the em dash.
- Show the formatted numeric value without inventing currency, because no unit is specified. Use an understandable polite output announcement.
- Clear selection in the different-size Apply path before changing appliedPaperSize. Draft changes and same-size Apply do not clear it.

## Risks and blockers

- Copied price state can become stale; store identity only and derive from current data.
- Price or array-index identity fails for duplicates and sparse rows; compare quantity plus business day.
- Manually interactive td elements require recreated semantics; use native buttons and keep unavailable cells control-free.
- Striped backgrounds can obscure selection or focus; verify explicit styles and contrast in a real browser.
- Effect-based reset permits a transient old price after Apply; clear synchronously in the submit path.
- Hover-like styling would blur T06 ownership; limit T04 to persistent selection, focus, and pointer affordance.
- The missing reference prevents pixel comparison; requirements-based browser QA remains required.
- Prior shipping evidence is locally modified; preserve it and isolate T04's index hunk during later commits.

No unresolved blocker prevents implementation.
