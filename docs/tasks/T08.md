## Goal

Update the UI layout so it is ready for cart logic without implementing that logic yet: add an Add to Cart action area below the table (button plus the selected item's Order price), remove the Order price currently shown beside `appliedPaperSize`, enlarge and circularize the `appliedPaperSize` badge, and add a (currently inert) shopping cart icon above the table, opposite the paper-size form.

## Acceptance criteria

1. A new component renders below `PriceTable` (inside or alongside `PricePanel`) containing an "Add to Cart" `<button>` and the Order price of the currently selected cell.
2. The Add to Cart button is disabled (native `disabled` attribute, not just a visual style) when `selectedCell` is `null`, and enabled when a cell is selected; clicking it while enabled has no persistent effect in this task (no state change, notification, or modal — that is T09).
3. The Order price value shown next to the Add to Cart button behaves exactly as the existing Order price did (em dash before selection, derived formatted price after), reusing the existing derivation and `formatPrice`.
4. The Order price display previously shown beside `appliedPaperSize` is removed from that location.
5. The `appliedPaperSize` badge is visually enlarged (font size and padding) and wrapped in a circular background (equal border-radius/width/height, or `border-radius: 50%`), remaining legible for all four paper-size labels (A4, A5, B4, B5).
6. Above the table, in the same row as the paper-size selection form, a shopping cart icon is added on the opposite side of the row from the form (e.g. form on one side, icon on the other, using flex/grid spacing already established in the layout).
7. The cart icon is a real interactive control (a `<button>` with an accessible name such as "View cart" or `aria-label`), but in this task clicking it has no effect yet (no modal opens) — it exists as a layout placeholder for T09.
8. The cart icon and the Add to Cart bar are keyboard-operable and have visible focus styles consistent with existing controls.
9. Layout remains responsive at the existing breakpoint(s) already defined in the CSS Modules (no horizontal overflow, no overlapping controls at narrow widths).
10. No new application state, dependency, global store, or behavior beyond enabling/disabling the button from existing `selectedCell` is introduced.
11. Existing automated tests continue to pass; new/updated tests cover the button's disabled/enabled states tied to selection and the presence/accessible name of the cart icon and the relocated Order price.
12. The final diff is scoped; acceptance criteria and the diff are inspected; tests, formatter, lint, and build pass; a real Chrome or Firefox check confirms the new layout, badge styling, and responsive behavior.

## Scope and non-goals

Scope: new "Add to Cart" bar component (button + Order price), removal of the old Order price location, `appliedPaperSize` badge restyling, and a new cart icon button placed opposite the paper-size form — all wired only to existing selection state.

Do not implement cart state, adding items, a success notification, a cart modal, quantity controls, item removal, total price, or a Checkout button (all T09). Do not change selection, hover, See more, Apply, or API behavior. Do not add a global store, routing, a backend, or any UI/icon library dependency.

## Implementation assumptions

These task-level choices are separate from assignment requirements:

- The cart icon is implemented as an inline SVG inside a native `<button>`, styled via CSS Modules/tokens, to avoid any icon-library dependency.
- "Opposite side of the row" from the paper-size form is implemented with flex layout (`justify-content: space-between` or equivalent) so the form and the cart icon sit at opposite ends of the same header row; exact spacing is a visual-design detail resolved during implementation.
- The Add to Cart bar is a new component (e.g. `AddToCartBar`) placed after `PriceTable` inside `PricePanel`, receiving `selectedCell`/`selectedPrice` as props rather than owning new state.
- The circular `appliedPaperSize` wrapper uses a fixed-aspect (equal width/height) container so it renders as a true circle regardless of label length; if a label would overflow, font-size is reduced rather than the circle becoming an ellipse.
